# Python в «Астерионе»

В игре 40 новых задач: p01–p10 на уровнях 1–10, p11–p40 на уровнях
13, 16, …, 100. В Android используется настоящий CPython 3.12.15 через
Chaquopy 17.2.0, в отдельном процессе приложения. В браузерной версии работает
CPython 3.12.1 через Pyodide 0.26.4 в Web Worker. Оба варианта полностью
локальны. Ответы не проверяются поиском слов в исходнике.
Задачи не требуют PyTorch, NumPy, сервера, регистрации или оплаты.

## Содержание

Первые десять задач знакомят с рабочим ядром синтаксиса: строки и преобразования,
списки/словари/множества, ветвления и циклы, функции и возвращаемые значения,
именованные параметры, изменяемые объекты, методы, классы и композиция,
исключения, импорт, контекстный менеджер и ленивые генераторы. Это не обещание
охватить все специальные конструкции языка: метаклассы, дескрипторы и async
не являются стартовой учебной целью.

Дальше идут практические функции для устройств леса: аудит утечки между
выборками, голосование и поиск соседей, объединение интервалов, потоковое
среднее, clipping, softmax, padding, батчи, причинная маска, top-k, LRU-кэш,
чанки, версии источников, RRF, схема tool-call, retry, редактирование приватных
полей, идемпотентный резерв энергии, низкоранговое обновление, int8-квантизация,
сериализация сообщений, взвешенные оценки, калибровочные корзины, расписание,
топологический порядок, BFS и задача о рюкзаке 0/1.

Задачи сравнивались с 20 функциями первой версии. Например, вместо прежнего
распределения групп по train/validation теперь требуется отчёт о числе записей
общего происхождения в двух уже готовых наборах. Задачи на two-sum, прибыль,
скобки и самую длинную уникальную подстроку не переиспользуются.

`web/python/exercises.json` содержит условие, заготовку, пример, объяснение,
подсказку, критерии и эталон. Эталон доступен игроку только через явное действие
«Разобрать эталон», которое интерфейс помечает как помощь. Локальное приложение
не пытается криптографически скрывать собственные учебные материалы.

## Проверка решения и связь с игрой

`web/python/validator.py` вызывает функции/классы игрока на конкретных входах.
Есть обычные случаи, граничные условия и вариант `transfer` с изменёнными данными.
Проверяются значения, ошибки неверного входа, отсутствие мутации, независимость
экземпляров и возвращаемых контейнеров, ленивость генератора, LRU-семантика,
идемпотентность и другие условия соответствующих задач.

Результат `artifact` содержит имя операции, вход и `repr` реально возвращённого
программой игрока результата. Он создаётся даже для неверной функции, если та
вернула значение. Вывод не подменяется эталоном. Успех открывает возможность
применить устройство; настройка учебной механики боя проверяется отдельно.

Тесты конечны: они дают полезную проверку контракта, но не математическое
доказательство правильности произвольного алгоритма. Отдельные задания на
объяснение и перенос нужны для проверки понимания.

## API

```js
import {PythonRunner} from './js/python-runner.js';
const runner = new PythonRunner({onStatus: message => console.log(message)});
await runner.init();
const result = await runner.run({
  exerciseId: 'p01', code: sourceText, variant: 'practice', timeoutMs: 15000
});
runner.stop();
```

`result`: `status` (`passed`, `failed`, `error`, `timeout`, `cancelled`),
`stdout`, `stderr`, `feedback`, `checks: [{name,passed,message}]`,
`artifact: {label,input,output} | null`. Ошибки подготовки помечены
`phase: "initialization"`; они не являются неправильным решением игрока.

`PythonRunner` автоматически выбирает Android bridge при наличии методов
`pythonInit`, `pythonRun`, `pythonStop`; в обычном браузере он использует Worker.
Android callback `window.onNativePythonMessage` получает JSON-события с уникальным
`requestId`. Сообщение `reset` сбрасывает готовность всех адаптеров, но не
подменяет отдельный ответ `timeout` или `cancelled`.

`web/python/native_runner.py` — точка входа Android: `run(id, code, variant)`
возвращает JSON-строку того же формата и использует тот же `validator.py`.
Java отсчитывает лимит выполнения после сигнала старта программы от сервиса;
подготовка среды имеет отдельный срок ожидания. «Стоп» и таймаут завершают
процесс Python, поэтому бесконечный цикл не блокирует интерфейс.

На каждый запуск создаётся отдельный словарь глобальных переменных программы.
`stdout`/`stderr` ограничены 32768 символами на поток. В браузере таймер
работает в основном JS-потоке; таймаут или «Стоп» завершает Worker. Следующий запуск создаёт интерпретатор заново. Фатальные ошибки подготовки
также завершают Worker: сообщения `API.on_fatal` и `onAbort` закреплённой версии
передаются интерфейсу вместе со стеком. Ошибка загрузки имеет статус `error`,
а `cancelled` используется для пользовательской остановки. Время загрузки
интерпретатора не входит в лимит выполнения. На фоне Android интерфейс сохраняет
черновик и отменяет вычисление.

В браузерной версии Worker отделяет выполнение от интерфейса и работает
в браузерных ограничениях.
Это учебная среда для собственного кода, а не система безопасного исполнения
враждебных программ: Pyodide позволяет импортировать `js`, и намеренно написанный
код может обращаться к браузерным API Worker. Файлы Python находятся в виртуальной
файловой системе интерпретатора; прямого доступа к системным файлам Android через этот браузерный вариант нет.
Нативный сервис Android является отдельным процессом приложения, а не
песочницей для враждебного кода. В учебных заданиях используется стандартная
библиотека, а файловое упражнение работает с `io.StringIO`.

## Офлайн-ресурсы и лицензии

Android APK содержит Chaquopy 17.2.0, CPython 3.12.15 и стандартную
библиотеку для arm64-v8a и x86_64; дополнительных загрузок при запуске нет.
Происхождение и лицензии нативных компонентов фиксируются сборкой Android.
Нативный backend выбран после проверки 80/80 вариантов непосредственно
в Android: он не зависит от запуска WebAssembly внутри WebView.

Все файлы в `web/vendor/pyodide` включаются в APK. Загружаются локально:
`pyodide.js`, `pyodide.asm.js`, `pyodide.asm.wasm`, `python_stdlib.zip`,
`pyodide-lock.json`; `pyodide.mjs` сохранён из той же версии, но не используется.
Удалённые пакеты не устанавливаются. Native asset server должен выдавать Wasm
как `application/wasm`. Не нужны COOP/COEP или SharedArrayBuffer: прерывание
реализовано завершением Worker.

Pyodide распространяется по MPL-2.0, CPython — по PSF License с включёнными
сторонними уведомлениями. Полные лицензии, ссылки на исходный код и контрольные
суммы находятся в `web/vendor/pyodide/NOTICE.md`, `LICENSE.*`, `SHA256SUMS`.

## Воспроизводимая проверка

```sh
python3 tests/test_python.py
python3 tests/test_python.py --browser
python3 tests/test_native_python.py
python3 tests/browser_native_adapter.py
```

Первый запуск проверяет 40 эталонов на обоих вариантах (80 выполнений),
непройденные заготовки, метаданные, шесть правдоподобно неверных алгоритмов,
нарушение порядка ключей и возврат ссылок на входные словари.
Режим `--browser` дополнительно использует установленный Chromium и Playwright,
поднимает временный localhost-сервер, блокирует все внешние запросы и запускает
те же 80 программ через фактический CPython/Wasm. Проверяются синтаксические
ошибки, настоящий stdout, артефакт неверной функции, переполнение вывода,
бесконечный цикл, остановка и восстановление интерпретатора. Отдельно внедряются
фатальная ошибка и abort на этапе загрузки, чтобы проверить сообщение об ошибке,
отсутствие вечного ожидания и последующее восстановление. Результат:
`artifacts/python-browser-tests.json`. Отдельные Android-проверки относятся
к APK и описаны в общем отчёте проекта.

Нативный glue отдельно проходит 80 вариантов, проверку вывода, ошибок и
изоляции переменных. Тест адаптера проверяет корреляцию запросов, Unicode,
порядок reset/timeout, отмену, игнорирование позднего ответа, ошибку подготовки
и восстановление. Этот тест протокола использует имитацию Java-host и не
заменяет реальные проверки установленного APK.
